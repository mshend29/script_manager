1. Memahami Project .smproj

Setiap project Script Manager disimpan sebagai satu file .smproj. Secara internal file tersebut adalah database SQLite yang menyimpan data kerja dan konfigurasi project.

Disimpan di .smprojTetap eksternal
Project Settings, metadata source, episode, dialogue, character, talent, cast mapping, recording status, tracking status, validation state, dan audit history. Source Excel, Stem / Mixdown / Export Folder, Setoran Folder, serta Main Drive / Material / Delivery URL.
Memindahkan file .smproj tidak otomatis memindahkan source Excel atau folder output. Jika lokasi source/output berubah, perbarui path melalui Project Settings.

Save, Save As, Duplicate

  • Save menyimpan perubahan ke project aktif.
  • Save As membuat file .smproj baru dengan identitas project yang sama.
  • Duplicate membuat salinan data sebagai project baru dengan identitas project baru.
  • Open Recent menampilkan project terakhir yang pernah dibuka dan masih tercatat oleh aplikasi.
  • Close menutup project aktif dan mengembalikan aplikasi ke kondisi tanpa project.

2. PROJECT dan Project Settings

Tab PROJECT adalah titik awal untuk membuat, membuka, menyimpan, dan mengelola project serta source.

Project Dashboard

Dashboard menampilkan ringkasan project dan pekerjaan yang membutuhkan perhatian, termasuk jumlah episode, character, talent, dialogue, kebutuhan review, recording progress, stem/delivery, revision, dan output warning jika tersedia.

Project Settings — Project

FieldFungsi

Project CodeKode project yang dapat digunakan sebagai identitas kerja/nama file awal.
ClientNama client atau pihak pemilik project.
Start DateTanggal mulai project.
Project FileLokasi file .smproj yang sedang dibuka. Ditampilkan sebagai informasi.
Main DriveURL navigasi ke drive utama client/project.
Material FolderURL material.

Project Settings — Source

Source Folder menunjuk folder tempat file Excel naskah berada. Gunakan Get Source Filenames untuk membaca nama file source dan membantu memeriksa pola episode.

Episode diekstrak dari nama file menggunakan:

  • Before Episode Number — karakter/teks sebelum nomor episode.
  • After Episode Number — karakter/teks setelah nomor episode.

Contoh: jika nama file mengandung 第87集, maka 第 dapat digunakan sebagai delimiter sebelum nomor dan 集 sebagai delimiter setelah nomor.

Project Settings — Track / Output

Project Settings juga menyediakan:

  • Stem / Mixdown / Export folder.
  • Setoran Folder.
  • Audio Format WAV.
  • Sample Rate, Bit Depth, dan Channels.

3. Source Excel dan Sync Source

Sync Source

Sync Source adalah satu-satunya tindakan untuk memasukkan dan memperbarui source naskah. Initial sync dan incremental sync memakai tombol yang sama. Alur internalnya mencakup scan/fingerprint, workbook inspection, parsing, normalization, character/talent resolution, validation, read-only preview, safety backup, transactional apply, lalu audit.

Jika ditemukan masalah yang membuat sync tidak aman—misalnya duplicate episode, file yang tidak dapat diproses, atau dialogue lineage yang ambigu—aplikasi menghentikan commit agar database tidak berubah sebagian.

Setelah sync pertama, sistem hanya memproses source yang perlu diperbarui:

  • New — file source baru.
  • Changed — source yang berubah.
  • Restored — source yang sebelumnya missing lalu tersedia kembali.
  • Unchanged — tidak perlu diparse ulang.
Persistent dialogue identity dipisahkan dari source signature. Recording history dan mapping manual tetap dipertahankan ketika source direvisi. Jika recording lama tidak lagi sesuai source terbaru, DIALOG menampilkan Source Revised. Tracking downstream hanya diinvalidasi pada scope Episode + Talent + Character yang benar-benar terkena perubahan semantic.
Setelah Apply berhasil, PROJECT dashboard dan workspace aktif langsung membaca data terbaru. SCRIPT, DIALOG, TRACKING, dan DATA yang belum dibuka ditandai dirty dan otomatis reload saat dibuka. Pengguna tidak perlu menjalankan Refresh View manual.

4. SCRIPT

Tab SCRIPT digunakan untuk membaca hasil naskah yang sudah masuk ke database project.

Kontrol utama:

  • Episode — pilih episode tertentu atau All.
  • Search — cari isi yang ditampilkan pada view Script.
SCRIPT membaca data yang sudah di-commit ke .smproj. Mengubah Excel tidak mengubah database sampai source diproses melalui Sync Source. Setelah Apply berhasil, view otomatis mengikuti project revision terbaru.

5. DIALOG dan Recording

Tab DIALOG adalah workspace untuk memilih talent, tokoh, dan episode lalu menandai progress recording dialogue.

Filter dan navigasi

  • Talent — pilih talent.
  • Tokoh — pilih character/tokoh yang terkait.
  • Episode — pilih episode.
  • Prev / Next — berpindah episode.
  • Open Source File — membuka file source untuk selection yang mempunyai source terkait.

Cast dan daftar dialog

Panel cast menampilkan pasangan TOKOH dan TALENT. Tabel dialog menampilkan checkbox recording, IN, OUT, dan DIALOG.

Gunakan:

  • checkbox per dialog untuk menandai dialog yang sudah direkam;
  • Check All untuk menandai semua dialog pada scope aktif;
  • Uncheck All untuk membatalkan tanda semua dialog pada scope aktif;
  • Copy All Dialog untuk menyalin isi dialog pada selection yang sedang dibuka.
Recording status disimpan di project dan dipakai oleh TRACKING untuk menghitung progress. Karena itu checkbox DIALOG adalah data workflow, bukan sekadar tampilan.

6. TRACKING

TRACKING merangkum status pekerjaan per talent, character, dan episode.

Episode status

View tracking menampilkan detail episode dan status. Pemilihan episode dapat menggunakan tombol Prev/Next dan filter yang tersedia pada workspace.

Revision

Episode detail menyediakan tindakan Mark Revision dan Clear Revision sesuai status saat ini.

Track Files

Workspace Track Files menyediakan fungsi untuk mencocokkan file output dengan struktur tracking, termasuk:

  • Match & Rename Episode;
  • Batch Match & Rename Talent;
  • Refresh Files;
  • Track Name Suggestion.

Output Health

Output Health menampilkan ringkasan file output seperti Stemmed Episodes, Delivered Episodes, dan Warnings. Gunakan bagian ini untuk menemukan file output yang tidak sesuai ekspektasi workflow.

7. DATA dan Validation

Tab DATA digunakan untuk memeriksa kesehatan data, mapping, unresolved source, dan hasil validation.

Overview

Menampilkan ringkasan data dan health project.

Character Mapping

Menampilkan character dan mapping talent. Mapping dapat di-Lock atau Unlock sesuai kebutuhan workflow.

Character Alias

Character Alias digunakan ketika variasi nama dari source sebenarnya merujuk ke character canonical yang sama.

  • Set as Alias — jadikan character terpilih sebagai alias character lain.
  • Add Alias Name… — tambahkan teks alias.
  • Remove Alias / Restore — hapus alias atau kembalikan character.

Talents

Menampilkan data talent yang sudah dikenal oleh project.

Unresolved

Digunakan untuk source/cast yang belum dapat diselesaikan otomatis dan masih membutuhkan review manual.

Sources

Menampilkan informasi source file yang tersimpan di database project.

Validation

Validation membagi issue menjadi kategori System, Review, dan Workflow. Gunakan Validate untuk menjalankan pemeriksaan data project.

8. TOOLS & Maintenance

Tab TOOLS menyediakan fungsi pemeliharaan dan shortcut ke lokasi kerja.

Diagnostics

  • Run Diagnostics — memeriksa kondisi project, database, folder, output, dan backup.
  • Audit History — melihat riwayat tindakan penting pada project.

Folder shortcuts

TOOLS menyediakan shortcut untuk membuka Project Folder, Source Folder, Stem / Export, Setoran Folder, Backups Folder, dan Logs Folder.

Drive shortcuts

Main Drive, Material Drive, dan Delivery Drive dapat dibuka dari TOOLS jika URL sudah dikonfigurasi di Project Settings.

Database maintenance

  • Create Backup — membuat snapshot project.
  • Restore Backup — mengembalikan database project aktif dari snapshot yang valid.
  • Rebuild Index pada DATA — menjalankan pemeliharaan index SQLite tanpa menghapus data.

9. Backup, Restore, dan Recovery

Create Backup

Backup disimpan sebagai file .smproj di application data per-user. Backup tidak menyalin source Excel atau file audio/output eksternal.

Restore Backup

Restore Backup mengganti database project aktif menggunakan snapshot yang dipilih. Sebelum restore, aplikasi membuat safety backup dari kondisi saat ini.

Recover Project

Recover Project digunakan untuk membuat file .smproj baru dari snapshot backup, misalnya ketika project asli hilang atau ketika ingin memulihkan ke file terpisah.

Restore dan Recover adalah dua operasi berbeda. Restore bekerja pada project aktif, sedangkan Recover menghasilkan file project hasil pemulihan.

10. Instalasi, Portable Build, dan File Association

Distribusi Windows tersedia dalam dua bentuk:

  • Portable ZIP — dapat diekstrak dan dijalankan langsung. Mode ini tidak mendaftarkan .smproj ke Windows.
  • Installer — memasang Script Manager untuk user aktif dan mendaftarkan .smproj sebagai Script Management Project. Setelah instalasi, double-click file project akan membuka Script Manager.
Installer bekerja per-user dan tidak memerlukan instalasi system-wide. File source Excel dan project .smproj tidak dipindahkan oleh installer.

11. Workflow kerja yang direkomendasikan

  1. Buat atau buka project .smproj.
  2. Periksa Project Settings, Source Folder, delimiter episode, dan folder output.
  3. Jalankan Sync Source untuk source awal.
  4. Periksa DATA → Unresolved / Validation jika ada issue.
  5. Gunakan SCRIPT untuk membaca naskah hasil import.
  6. Gunakan DIALOG untuk proses recording dan checkbox progress.
  7. Pantau TRACKING untuk recording, revision, stem, delivery, dan output health.
  8. Jika client merevisi Excel, perbarui source lalu jalankan Sync Source lagi.
  9. Buat backup pada milestone penting atau sebelum operasi maintenance.
