Panduan Pengguna Script Manager

Panduan operasional untuk mengelola naskah drama pendek vertikal dari source Excel sampai rekaman, tracking, stem, dan setoran.

Cara paling aman menggunakan Script Manager

Anggap file .smproj sebagai pusat keadaan kerja proyek. Excel tetap menjadi sumber eksternal. Perubahan pada Excel baru masuk ke proyek melalui Sinkronkan Sumber.

Alur utamanya:

Proyek → Sumber Naskah → Sinkronkan Sumber → NASKAH / DIALOG → TRACKING → DELIVERY

Topik yang sering dicari:
Membuat Proyek Baru Sinkronkan Sumber Merekam Dialog Memahami Tracking Backup & Recovery Troubleshooting

Membuat Proyek Baru

Gunakan Proyek Baru untuk membuat proyek yang langsung siap kerja. Wizard terdiri dari lima milestone dan tidak membuat file permanen sampai tahap akhir.

1. Inisialisasi Proyek

  • Nama Proyek, Kode Proyek, Klien, dan Tanggal Mulai wajib.
  • Pilih lokasi penyimpanan file proyek.
  • Nama file proyek baru mengikuti format KODE - NAMA PROYEK.smproj.
  • Karakter yang tidak valid untuk filename Windows disanitasi hanya pada nama file; metadata proyek tidak diubah.
  • Jika target filename sudah ada, Create diblokir agar file lama tidak tertimpa.
Auto-code: sebelum Kode Proyek diedit manual, kode dapat mengikuti Nama Proyek. Setelah kode diedit manual, perubahan nama tidak menimpanya lagi.

2. Sumber Naskah

Pilih Folder Sumber, tentukan delimiter nomor episode, lalu jalankan Source Preflight. Wizard memeriksa seluruh file .xlsx/.xlsm, bukan hanya satu contoh.

3. Sumber Audio

Tentukan Folder Stem / Mixdown / Export, Folder Setoran, dan format WAV (sample rate, bit depth, channel).

4. Folder & Tautan

Periksa kembali folder operasional dan, bila diperlukan, isi Drive Utama URL, Material URL, atau Setoran URL. URL browser bersifat opsional.

5. Review & Buat Proyek

Review menampilkan ✓ valid, ⚠ warning, atau ✕ blocker. Tombol Buat Proyek baru aktif ketika blocker selesai.

Setelah Create diklik, aplikasi membuat .smproj secara transaksional dan menjalankan Initial Source Sync otomatis. Proyek baru masuk Recent Projects hanya setelah proses berhasil.
Jika source berubah setelah preflight, wizard menganggap hasil preflight lama stale dan meminta preflight ulang. Ini mencegah project dibuat berdasarkan source yang sudah berubah.

Apa yang terjadi setelah Settings diubah?

  • Perubahan source/delimiter menandai data source-dependent perlu disinkronkan kembali; gunakan F5 / Sinkronkan Sumber.
  • Perubahan folder output memicu refresh filesystem Tracking/Delivery.
  • Perubahan URL saja tidak menyebabkan source sync.
  • Path existing yang sementara offline dapat muncul sebagai warning agar proyek tetap bisa dibuka.
Untuk konfigurasi baru: Folder Sumber tidak boleh sama dengan Folder Stem atau Folder Setoran. Stem dan Setoran boleh sama, tetapi aplikasi memberi warning karena file dapat tercampur.

Validasi dilakukan untuk seluruh file

  • Dua file yang menghasilkan episode sama menjadi blocker.
  • Pola filename yang benar-benar berbeda menjadi blocker.

Source Preflight

Preflight adalah pemeriksaan read-only sebelum source boleh digunakan untuk membuat proyek baru.

  1. Aplikasi memindai semua workbook kandidat.
  2. Filename dan nomor episode divalidasi.
  3. Workbook dibuka melalui inspector produksi.
  4. Naskah diparse melalui parser produksi.
  5. Masalah ditampilkan tanpa menulis database.

Preflight dapat mendeteksi workbook corrupt, struktur yang tidak dikenali, parsing error, duplicate episode, atau filename yang tidak cocok dengan delimiter.

Preflight tidak membuat .smproj, tidak menulis database, dan tidak mengubah recording/tracking. Ia hanya membuktikan source siap diproses.

Sinkronkan Sumber

Sinkronkan Sumber adalah satu user-facing action untuk import pertama dan refresh source berikutnya. Shortcut-nya adalah F5.

Alur aman Sinkronkan Sumber

  1. Prepare: scan, inspect, parse, dan reconcile dilakukan tanpa menulis proyek.
  2. Preview: aplikasi menunjukkan perubahan yang akan diterapkan.
  3. Apply: setelah disetujui, aplikasi membuat safety backup.
  4. Transactional commit: perubahan diterapkan sebagai satu transaksi.
  5. Audit: hasil aktual dicatat ke riwayat proyek.

Jenis perubahan source

  • Baru — workbook/episode baru.
  • Berubah — source memiliki perubahan semantik.
  • Dipulihkan — source yang sebelumnya hilang tersedia kembali.
  • Tidak Berubah — tidak perlu diparse ulang.
Jika Preview menunjukkan kondisi ambigu atau error yang dapat merusak lineage, jangan paksa Apply. Perbaiki source/configuration lalu jalankan Sinkronkan Sumber lagi.
Setelah Apply sukses, workspace lain otomatis mengikuti revision proyek terbaru. Operator tidak perlu menjalankan “Refresh View” per halaman.

Revisi Sumber & “Sumber Direvisi”

Script Manager mempertahankan persistent dialogue identity sehingga revisi client tidak otomatis menghapus riwayat rekaman.

PerubahanDampak
Formatting Excel sajaTidak mereset recording atau tracking karena tidak ada perubahan semantik.
Teks/timecode dialog berubahLineage tetap dipertahankan bila reconciliation aman; recording lama tetap tercatat dan line ditandai Sumber Direvisi.
Cast berubahHistory dipertahankan; scope Tracking lama/baru yang terpengaruh dapat diinvalidasi.
Dialog ditambah/dihapusScope Tracking yang benar-benar terpengaruh diupdate, bukan seluruh proyek.
“Recorded” dan “Sumber Direvisi” dapat muncul bersamaan. Artinya line pernah direkam, tetapi source terbaru berbeda dan operator perlu menilai apakah perlu re-record.

NASKAH

NASKAH digunakan untuk membaca hasil source yang sudah tersimpan di .smproj.

  • Pilih Episode atau Semua.
  • Gunakan Cari untuk mencari isi naskah.
  • Jika Excel di luar aplikasi berubah, NASKAH tidak berubah sampai Sinkronkan Sumber selesai.
Gunakan NASKAH untuk membaca data operasional proyek, bukan untuk memeriksa file Excel mentah.

DIALOG & Rekaman

DIALOG adalah workspace utama untuk sesi rekaman.

Filter utama

  • Talent — pilih pengisi suara.
  • Tokoh — pilih character yang dibawakan.
  • Episode — pilih episode kerja.
  • Cari — temukan dialog tertentu.

Mencatat rekaman

  • Centang checkbox per dialog setelah line selesai direkam.
  • Centang Semua menandai semua line dalam scope aktif.
  • Hapus Centang Semua membatalkan semua tanda pada scope aktif.
  • Buka File Sumber membantu operator merujuk workbook terkait.
Checkbox Recorded adalah data workflow yang disimpan ke proyek dan dipakai oleh Tracking. Jangan gunakan checkbox hanya sebagai penanda sementara.
Line berstatus Sumber Direvisi membutuhkan perhatian. History rekaman tetap ada; operator memutuskan apakah revisi memerlukan re-record.

TRACKING

TRACKING memberikan gambaran padat status episode per Talent/Tokoh. Warna adalah indikator utama dan legend/tooltip menjelaskan artinya.

Status umumMakna operasional

Revisi source hanya menginvalidasi Episode + Talent + Tokoh yang benar-benar terkena perubahan semantik. Scope lain seharusnya tetap stabil.

DELIVERY

DELIVERY adalah workspace khusus output. Gunakan filter Talent lalu pilih salah satu mode:

File Track

  • Melihat file output yang ditemukan.
  • Mencocokkan file dengan episode/talent.
  • Menggunakan saran nama track.
  • Meninjau warning penamaan, termasuk konteks Revision.

Kondisi Output

Menampilkan kesehatan output seperti episode selesai stem, episode disetor, dan warning. Gunakan bagian ini untuk menemukan mismatch filesystem sebelum setoran dianggap selesai.

Folder Stem dan Setoran adalah filesystem. Link Google Drive browser tidak menggantikan folder output.

DATA, Tokoh, Talent & Alias

DATA digunakan untuk memeriksa struktur dan kualitas data proyek.

Pemetaan Tokoh & Talent

Gunakan mapping untuk menghubungkan tokoh dengan talent. Mapping yang sudah benar dapat dikunci agar tidak berubah tanpa sengaja.

Tokoh Alias

Gunakan Tokoh Alias ketika variasi penulisan dari source sebenarnya merujuk ke tokoh kanonis yang sama.

  • Jadikan Alias — gabungkan variasi ke tokoh kanonis.
  • Tambah Nama Alias… — tambahkan bentuk nama lain.
  • Hapus Alias / Pulihkan — kembalikan hubungan alias sesuai kebutuhan.

Belum Dipetakan

Menampilkan source/cast yang tidak dapat diselesaikan otomatis dan membutuhkan keputusan operator.

Sumber & Validasi

Gunakan bagian Sumber untuk memeriksa metadata source yang diketahui proyek. Validasi membantu memisahkan masalah blocker, warning, dan kondisi yang perlu review.

Peralatan & Pemeliharaan

TOOLS berisi tindakan teknis yang tidak diperlukan dalam workflow normal setiap hari. Gunakan ketika ada kebutuhan maintenance atau diagnosis.

  • Bangun Ulang Indeks dapat dipakai bila indeks pencarian/pendukung perlu dibangun ulang.
  • Cadangkan membuat backup proyek aktif.
  • Fitur diagnosis/maintenance lain sebaiknya digunakan setelah memahami dampaknya.
Untuk perubahan source harian, jangan gunakan Tools sebagai pengganti Sinkronkan Sumber. Gunakan F5.

Cadangan & Pemulihan

Cadangkan

Membuat salinan aman proyek. Source sync Apply juga menggunakan safety backup sebelum write transaksional.

Pulihkan Cadangan

Gunakan ketika ingin kembali ke keadaan proyek dari backup yang tersedia. Pastikan memilih backup yang benar dan jangan menghapus sumber backup sampai hasil recovery diverifikasi.

Pulihkan Proyek

Membuat proyek aktif dari file recovery/backup sambil menjaga file sumber recovery tetap utuh. Recovery tidak boleh melakukan overwrite diam-diam terhadap project target yang sudah ada.

Backup .smproj tidak menyertakan Excel, Stem, atau Setoran yang berada di luar file proyek. Backup external files tetap perlu mengikuti kebijakan produksi tim.

Alur Kerja Harian yang Disarankan

  1. Buka proyek dan periksa Dashboard / Needs Attention.
  2. Jika client mengirim source baru/revisi, letakkan workbook di Folder Sumber.
  3. Tekan F5 / Sinkronkan Sumber, baca Preview, lalu Apply bila benar.
  4. Periksa DATA bila ada unresolved mapping atau validasi.
  5. Gunakan DIALOG untuk sesi recording dan tandai line yang selesai.
  6. Periksa TRACKING untuk scope yang siap stem atau membutuhkan perhatian.
  7. Gunakan DELIVERY untuk mencocokkan File Track dan memeriksa Kondisi Output.
  8. Buat backup pada checkpoint penting, terutama sebelum perubahan besar di luar workflow source sync normal.

FAQ

Apakah saya perlu menekan refresh di setiap halaman setelah F5?

Tidak. Setelah Sinkronkan Sumber berhasil, aplikasi menandai revision data proyek dan workspace lain memuat data terbaru saat diperlukan.

Apakah Excel adalah database utama?

Tidak. Excel adalah source eksternal. .smproj menyimpan operational state seperti recording, mapping, tracking, audit, dan konfigurasi.

Apakah Save As sama dengan Duplicate?

Tidak. Save As mempertahankan project identity; Duplicate membuat identity proyek baru.

Apakah folder Stem boleh sama dengan Folder Setoran?

Boleh, tetapi aplikasi memberi warning karena export dan setoran dapat tercampur. Folder Sumber tidak boleh sama dengan Stem atau Setoran untuk konfigurasi baru.

Apakah Drive URL wajib?

Tidak. URL browser bersifat opsional. Folder filesystem operasional tetap yang digunakan aplikasi untuk membaca/menilai file.

Apakah source revision menghapus recording lama?

Tidak. History dipertahankan. Jika source terbaru berbeda, line dapat ditandai Sumber Direvisi agar operator dapat mengambil tindakan.

Apa yang harus dilakukan jika masih bingung?

Gunakan kotak Cari panduan... di kiri. Cari istilah tugas, misalnya preflight, tracking, drive, backup, atau revisi. Jika masalahnya teknis, gunakan Laporkan Masalah.

Panduan ini disimpan offline bersama Script Manager sehingga tetap dapat dibaca tanpa koneksi internet.
